# 示例：一段真实的一轮

> ⚠️ **状态：占位（PLACEHOLDER）**
> 这一页等作者把**别处会话里记录的真实一轮**脱敏后填进来。
> 绝不编造一段冒充实录——那正是这个 skill 反对的"虚假胜任感"。
> 在那之前，下面是**结构模板 + 脱敏清单**，告诉你（也告诉未来的作者）一轮长什么样。

---

## 一轮的结构（填的时候照这个走）

1. **靶点**：挖的是哪个改动 / 哪个 commit。（脱敏后：只写"某次改动"，不写 repo/公司）
2. **冷读 sub-agent 挖到的点**：最值得深挖、最可能"写得出但没真懂"的一个点。（抽象）
3. **回合**：
   - skill 先让用户产出（招②"为什么这么做/排除过什么"，或招④"先猜"）
   - 用户卡在哪 / 说了什么 / 沉默在哪（**原话，脱敏**）
   - skill 揭示落差（先肯定对的部分）
4. **顶点原理**：逼到的、能迁移的那条法则。
5. **成功信号**：用户最后说出的「这个改动我原来没想到的是 ___」。（一句就够）
6. **地图那一格**：写进 `~/.gan-zhong-xue/map.jsonl` 的那一行（脱敏版）。

---

## 脱敏清单（隐私铁则，填之前逐条过）

填进这一页（以及任何示例）的内容，**禁止**出现：

- [ ] 芯片型号 / 具体器件名（如 STM32、ESP32…）→ 写"某 MCU""某 SoC"
- [ ] 寄存器名 / 地址（如 GPIO 基址 0x40020000、REG_CTRL…）→ 写"某寄存器/某地址"
- [ ] IP / URL / 端口
- [ ] 密钥 / token / 任何凭证
- [ ] 公司名 / 产品名 / 项目代号
- [ ] 内部代码路径、内部仓库名、内部工单号
- [ ] 可与人关联的个人信息

**只记抽象后的概念。** 拿不准就再抽象一层。

---

## 填写说明（给作者）

把别处会话里那轮的记录拿出来 → 按上面结构 → 过一遍脱敏清单 → 贴到这一页 → 把顶部的 PLACEHOLDER 标记删掉。

一段真实的、用户原话卡壳在哪、最后说出"我原来没想到的是___"的一轮，是这个仓库招揽独立测试者**最硬的资产**——比 README 写得多好都管用。
