## 一轮的结构（填的时候照这个走）

1. **靶点**：挖的是哪个改动 / 哪个 commit。（脱敏后：只写"某次改动"，不写 repo/公司）
2. **冷读 sub-agent 挖到的点**：最值得深挖、最可能"写得出但没真懂"的一个点。（抽象）
3. **回合**：
   - skill 先让用户产出（招②"为什么这么做/排除过什么"，或招④"先猜"）
   - 用户卡在哪 / 说了什么 / 沉默在哪（**原话，脱敏**）
   - skill 揭示落差（先肯定对的部分）
4. **岔路记录**：
   - 中途冒出的前置概念清单：两步测试结果（判靶内进图 vs 判外部前置搭桥 + `⏸` 格）。
   - 若发生“越问越不懂”或“换场好奇”，记下处理与最终是否回到主线。
5. **顶点原理**：逼到的、能迁移的那条法则。
6. **成功信号**：用户最后说出的「这个改动我原来没想到的是 ___」。（一句就够）
7. **地图那一格（v1.2.0 CLI 落盘格式示意）**：

```bash
python3 '<SKILL_DIR>/gzx_cli.py' save-cell <<'GZX_JSON_EOF'
{"概念":"某类配置驱动逻辑的注入边界","分层":"🟡","来源":"🟢自","先猜":"<揭示前用户脱敏原话，或写「因隐私约束未保存原文」>","证据":"<揭示后用户脱敏原话>","顶点原理":"数据与代码边界不隔离时，外来的配置输入就是可执行指令","验证题":"换到权限或模板引擎场景：如果一份外部报表模板支持表达式求值，风险和防线分别是什么？","用户更懂":"<用户补充的业务背景或无>","状态":"待复验","备注":"格式示意，非真实实录"}
GZX_JSON_EOF
```

`save-cell` 会在同一把文件锁内校验字段并同时追加到 `~/.gan-zhong-xue/map.jsonl` 与 `~/.gan-zhong-xue/map.md`。

## 脱敏清单（隐私铁则，填之前逐条过）

填进这一页（以及任何示例）的内容，**禁止**出现：

- [ ] 芯片型号 / 具体器件名（如 STM32、ESP32…）→ 写"某 MCU""某 SoC"
- [ ] 寄存器名 / 地址（如 GPIO 基址 0x40020000、REG_CTRL…）→ 写"某寄存器/某地址"
- [ ] IP / URL / 端口
- [ ] 密钥 / token / 任何凭证
- [ ] 公司名 / 产品名 / 项目代号
- [ ] 内部代码路径、内部仓库名、内部工单号
- [ ] 可与人关联的个人信息

**只记抽象后的概念。** 拿不准就再抽象一层。
